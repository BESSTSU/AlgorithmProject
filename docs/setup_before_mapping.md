# คู่มือเตรียมระบบก่อนเก็บแมพ (สำหรับมือใหม่)

ทำตามคู่มือนี้จนจบ แล้วโน้ตบุ๊กจะบังคับหุ่นหนึ่งตัวได้ และพร้อมเก็บแมพ SLAM
ขั้นเก็บแมพเองอยู่ใน [m8c_guide.md](m8c_guide.md) ส่วน A

ขั้นที่เขียนว่า "ทำครั้งเดียว" ไม่ต้องทำซ้ำในครั้งถัดไป

> **ที่มาของคำสั่งในคู่มือนี้**
> - ฝั่งโน้ตบุ๊ก: ตรวจจากเครื่องนี้แล้ว (WSL, ROS 2 Humble, แพ็กเกจ turtlebot3 รุ่น 2.3.6)
> - การตั้งค่าเครือข่าย WSL: จากเอกสารของ Microsoft
> - ฝั่งหุ่น: จากคู่มือทางการของ ROBOTIS ยังไม่เคยลองกับหุ่นของคุณ ถ้าผลไม่ตรงกับที่เขียน ให้จดไว้แล้วแจ้งกลับ

## รู้จักหน้าต่างที่จะใช้

มี 3 แบบ คู่มือจะบอกทุกครั้งว่าพิมพ์คำสั่งที่ไหน

| ชื่อในคู่มือ | คืออะไร | เปิดยังไง |
|---|---|---|
| **PowerShell** | เทอร์มินัลของ Windows | กดปุ่ม Windows พิมพ์ `PowerShell` แล้ว Enter |
| **เทอร์มินัล WSL** | Ubuntu ที่อยู่ในโน้ตบุ๊ก มี ROS 2 ติดตั้งอยู่ | พิมพ์ `wsl -d Ubuntu-22.04` ใน PowerShell |
| **เทอร์มินัลหุ่น** | หน้าจอของ Raspberry Pi บนหุ่น เข้าผ่าน SSH | ดูขั้น 4 |

**ระวัง:** โน้ตบุ๊กนี้มี Ubuntu สองตัว ROS อยู่ในตัวที่ชื่อ `Ubuntu-22.04` ซึ่งไม่ใช่ตัวที่เปิดขึ้นเองเมื่อพิมพ์ `wsl` เฉยๆ
ต้องพิมพ์ `wsl -d Ubuntu-22.04` ทุกครั้ง

เช็คว่าเปิดถูกตัว ในเทอร์มินัล WSL:

```bash
echo $ROS_DISTRO
```

**ควรเห็น:** `humble` ถ้าไม่มีอะไรขึ้น แปลว่าเปิดผิดตัว

## ขั้น 0: ของที่ต้องมี

- หุ่น 1 ตัวที่ชาร์จแบตแล้ว (เก็บแมพใช้ตัวเดียว)
- **Wi-Fi ที่ทั้งโน้ตบุ๊กและหุ่นต่อได้ และยอมให้อุปกรณ์คุยกันเอง**
  Wi-Fi ของมหาวิทยาลัยหรือที่สาธารณะมักกันไม่ให้อุปกรณ์คุยกัน แนะนำเราเตอร์ของตัวเองหรือ hotspot จากมือถือ
- ชื่อผู้ใช้และรหัสผ่านของ Raspberry Pi บนหุ่น (คู่มือ ROBOTIS ใช้ชื่อ `ubuntu` ส่วนรหัสผ่านคือค่าที่ตั้งไว้ตอนติดตั้ง)
- สนามที่สร้างเสร็จแล้ว

## ขั้น 1: ให้ WSL อยู่ในวงเครือข่ายเดียวกับหุ่น (ทำครั้งเดียว)

ปกติ WSL อยู่ในเครือข่ายจำลองของตัวเอง หุ่นจึงมองไม่เห็น ต้องเปลี่ยนเป็นโหมด mirrored

1. ใน **PowerShell** เปิด Notepad เพื่อสร้างไฟล์ตั้งค่า

   ```powershell
   notepad $env:USERPROFILE\.wslconfig
   ```

   Notepad จะถามว่าจะสร้างไฟล์ใหม่ไหม ตอบ Yes แล้วพิมพ์สองบรรทัดนี้ลงไป บันทึก แล้วปิด

   ```
   [wsl2]
   networkingMode=mirrored
   ```

2. ปิดหน้าต่าง WSL ทุกบาน แล้วใน **PowerShell**

   ```powershell
   wsl --shutdown
   ```

3. เปิด **PowerShell แบบ Run as administrator** (คลิกขวาที่ PowerShell แล้วเลือก Run as administrator) แล้วรัน

   ```powershell
   Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
   ```

   คำสั่งนี้เปิดให้เครื่องอื่นในวง Wi-Fi ต่อเข้ามาที่ WSL ได้ ควรทำเฉพาะบนเครือข่ายที่ไว้ใจได้
   ยกเลิกได้โดยรันคำสั่งเดิมแล้วเปลี่ยน `Allow` เป็น `Block`

4. เช็คผล ใน **PowerShell** ดู IP ของโน้ตบุ๊ก (บรรทัด IPv4 Address ของ Wi-Fi)

   ```powershell
   ipconfig
   ```

   แล้วเปิด **เทอร์มินัล WSL** ดู IP ของ WSL

   ```bash
   hostname -I
   ```

   **ควรเห็น:** เลข IP ของโน้ตบุ๊กอยู่ในผลของ `hostname -I` ด้วย (เช่น `192.168.1.23`)
   ถ้ายังเห็นแต่เลขที่ขึ้นต้นด้วย `172.` ให้ทำข้อ 1 และ 2 ใหม่

## ขั้น 2: ตั้งค่า ROS ฝั่ง WSL (ทำครั้งเดียว)

ใน **เทอร์มินัล WSL** รันสามบรรทัดนี้ทีละบรรทัด สองบรรทัดแรกเพิ่มการตั้งค่าลงไฟล์ `~/.bashrc`
ซึ่งเป็นไฟล์ที่รันทุกครั้งที่เปิดเทอร์มินัล

```bash
echo 'source ~/turtlebot3_ws/install/setup.bash' >> ~/.bashrc
echo 'export TURTLEBOT3_MODEL=burger' >> ~/.bashrc
source ~/.bashrc
```

เช็ค:

```bash
echo $ROS_DOMAIN_ID $TURTLEBOT3_MODEL
ros2 pkg prefix turtlebot3_cartographer
```

**ควรเห็น:** `70 burger` และบรรทัดที่ลงท้ายด้วย `turtlebot3_ws/install/turtlebot3_cartographer`

เลข `70` คือ `ROS_DOMAIN_ID` ของโน้ตบุ๊ก เครื่องที่จะคุยกันผ่าน ROS ต้องใช้เลขนี้ตรงกัน จำเลขนี้ไว้ใช้ในขั้น 4

## ขั้น 3: เปิดหุ่นและหา IP ของหุ่น

1. เปิดสวิตช์หุ่น รอประมาณ 1 นาทีให้ Raspberry Pi เปิดเครื่องและต่อ Wi-Fi
2. หา IP ของหุ่น ทำได้ทางใดทางหนึ่ง:
   - ดูรายชื่ออุปกรณ์ที่ต่ออยู่ในหน้าตั้งค่าของเราเตอร์หรือ hotspot
   - ต่อจอกับคีย์บอร์ดเข้ากับ Raspberry Pi แล้วพิมพ์ `hostname -I`
3. ใน **เทอร์มินัล WSL** ลองเรียกหุ่น (เปลี่ยน `192.168.1.50` เป็น IP ของหุ่น)

   ```bash
   ping -c 3 192.168.1.50
   ```

   **ควรเห็น:** สามบรรทัดที่ขึ้นต้นด้วย `64 bytes from` และ `0% packet loss`
   ถ้าไม่ได้ แปลว่าโน้ตบุ๊กกับหุ่นยังไม่ได้อยู่ Wi-Fi เดียวกัน หรือ Wi-Fi กันไม่ให้อุปกรณ์คุยกัน

ถ้าหุ่นยังไม่เคยตั้งค่า Wi-Fi หรือยังไม่ได้ติดตั้ง ROS บน Raspberry Pi ต้องทำตามหัวข้อ SBC Setup
ของคู่มือ ROBOTIS ก่อน: <https://emanual.robotis.com/docs/en/platform/turtlebot3/sbc_setup/>
(เลือกแท็บ Humble) ส่วนนั้นอยู่นอกคู่มือนี้

## ขั้น 4: เข้าไปที่หุ่นและเช็คการตั้งค่า

1. ใน **เทอร์มินัล WSL** เข้าไปที่หุ่นด้วย SSH

   ```bash
   ssh ubuntu@192.168.1.50
   ```

   ครั้งแรกจะถามว่าเชื่อถือเครื่องนี้ไหม พิมพ์ `yes` แล้วใส่รหัสผ่านของ Raspberry Pi (ตอนพิมพ์รหัสผ่านจะไม่มีตัวอักษรขึ้น เป็นเรื่องปกติ)
   หน้าต่างนี้กลายเป็น **เทอร์มินัลหุ่น** แล้ว สังเกตได้จากข้อความหน้าบรรทัดที่เปลี่ยนเป็นชื่อเครื่องของหุ่น

2. ใน **เทอร์มินัลหุ่น** ดูการตั้งค่า

   ```bash
   echo $ROS_DOMAIN_ID $LDS_MODEL $TURTLEBOT3_MODEL
   ```

   | ค่า | ที่ต้องการ |
   |---|---|
   | `ROS_DOMAIN_ID` | ต้องเท่ากับของโน้ตบุ๊ก คือ `70` (ค่าที่คู่มือ ROBOTIS ตั้งให้คือ `30`) |
   | `LDS_MODEL` | `LDS-01` หรือ `LDS-02` ตรงกับ LiDAR ที่ติดอยู่บนหุ่น จดค่านี้ไว้ |
   | `TURTLEBOT3_MODEL` | `burger` ถ้าว่างเปล่าไม่เป็นไร จะตั้งในขั้น 5 |

3. ถ้า `ROS_DOMAIN_ID` ไม่ใช่ 70 ให้แก้ในไฟล์ `~/.bashrc` ของหุ่น

   ```bash
   nano ~/.bashrc
   ```

   เลื่อนลงไปหาบรรทัด `export ROS_DOMAIN_ID=...` แก้เลขเป็น `70` กด `Ctrl+S` เพื่อบันทึก และ `Ctrl+X` เพื่อออก แล้วรัน

   ```bash
   source ~/.bashrc
   ```

4. เช็คนาฬิกา รันคำสั่งนี้ทั้งใน **เทอร์มินัลหุ่น** และใน **เทอร์มินัล WSL** อีกบาน

   ```bash
   date
   ```

   **ควรเห็น:** เวลาต่างกันไม่เกิน 1–2 วินาที Raspberry Pi ไม่มีนาฬิกาในตัว ถ้าไม่ได้ต่ออินเทอร์เน็ต เวลาจะเพี้ยน
   และการทำ SLAM มักมีปัญหาเมื่อเวลาของสองเครื่องไม่ตรงกัน ถ้าต่างกันมาก ให้ใช้ Wi-Fi ที่ออกอินเทอร์เน็ตได้แล้วรีบูตหุ่น
   (ข้อนี้เป็นคำแนะนำของผม ไม่ได้อยู่ในคู่มือ ROBOTIS)

## ขั้น 5: เปิดระบบของหุ่น

ใน **เทอร์มินัลหุ่น**

```bash
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_bringup robot.launch.py
```

**ควรเห็น:** ข้อความไหลขึ้นมาและมีบรรทัดเหล่านี้

```
Succeeded to open the port(/dev/ttyACM0)!
[turtlebot3_node]: Run!
[diff_drive_controller]: Run!
```

LiDAR บนหุ่นควรเริ่มหมุน **ปล่อยหน้าต่างนี้ค้างไว้ตลอด** ถ้าปิด หุ่นจะหยุดทำงาน
(สำหรับการเก็บแมพ ไม่ต้องใส่ `namespace:=...` ต่อท้ายคำสั่ง)

## ขั้น 6: เช็คจากโน้ตบุ๊กว่าเห็นหุ่น

เปิด **เทอร์มินัล WSL** บานใหม่ (เปิด PowerShell อีกบาน แล้วพิมพ์ `wsl -d Ubuntu-22.04`)

1. ดูรายการ topic

   ```bash
   ros2 topic list
   ```

   **ควรเห็น:** มี `/scan`, `/odom`, `/cmd_vel`, `/tf`, `/imu`, `/battery_state` อยู่ในรายการ
   ถ้าเห็นแค่ `/parameter_events` กับ `/rosout` แปลว่าโน้ตบุ๊กยังไม่เห็นหุ่น ดูตารางแก้ปัญหาท้ายคู่มือ

2. ดูว่าข้อมูล LiDAR ไหลจริง

   ```bash
   ros2 topic hz /scan
   ```

   **ควรเห็น:** `average rate` ประมาณ 5 (LDS-01) หรือ 10 (LDS-02) กด `Ctrl+C` เพื่อหยุด

3. ลองบังคับหุ่น **ยกหุ่นวางบนแท่นให้ล้อลอยก่อน** หรือวางบนพื้นที่โล่ง

   ```bash
   ros2 run turtlebot3_teleop teleop_keyboard
   ```

   | ปุ่ม | ผล |
   |---|---|
   | `w` / `x` | เพิ่ม / ลดความเร็วเดินหน้า |
   | `a` / `d` | เลี้ยวซ้าย / ขวา |
   | `s` หรือ spacebar | หยุดทันที |

   **ควรเห็น:** ล้อหมุนตามปุ่ม และหยุดเมื่อกด `s` กด `Ctrl+C` เพื่อออกจากโปรแกรม
   หน้าต่างนี้ต้องเป็นหน้าต่างที่เลือกอยู่ตอนกดปุ่ม

## พร้อมเก็บแมพเมื่อ

- [ ] `hostname -I` ใน WSL มี IP ของวง Wi-Fi
- [ ] `ping` จาก WSL ไปหุ่นได้
- [ ] `ROS_DOMAIN_ID` ของหุ่นกับโน้ตบุ๊กตรงกัน
- [ ] เวลาของหุ่นกับโน้ตบุ๊กตรงกัน
- [ ] bringup ขึ้น `Run!` และ LiDAR หมุน
- [ ] `ros2 topic list` ใน WSL เห็น `/scan`
- [ ] บังคับหุ่นด้วยคีย์บอร์ดได้ และกด `s` แล้วหยุด

ครบแล้วไปต่อที่ [m8c_guide.md](m8c_guide.md) ส่วน A ตอนเก็บแมพจะใช้หน้าต่าง 4 บาน:

| บาน | อยู่ที่ไหน | รันอะไร |
|---|---|---|
| 1 | เทอร์มินัลหุ่น | bringup (ขั้น 5) เปิดค้างไว้ |
| 2 | เทอร์มินัล WSL | `ros2 launch turtlebot3_cartographer cartographer.launch.py` จะมีหน้าต่าง RViz แสดงแมพขึ้นมา |
| 3 | เทอร์มินัล WSL | `ros2 run turtlebot3_teleop teleop_keyboard` สำหรับขับหุ่น |
| 4 | เทอร์มินัล WSL | คำสั่งวัดจุดอ้างอิงและบันทึกแมพ |

ตอนขับเก็บแมพ ให้ขับช้าๆ อย่าเปลี่ยนความเร็วหรือเลี้ยวกะทันหัน และพาหุ่นไปให้ครบทุกมุมของสนาม

## ตอนเลิกใช้

1. ในบานที่รันโปรแกรมอยู่ กด `Ctrl+C` ทีละบาน บาน bringup ปิดเป็นบานสุดท้าย
2. ใน **เทอร์มินัลหุ่น** สั่งปิด Raspberry Pi ก่อนปิดสวิตช์ เพื่อไม่ให้การ์ดหน่วยความจำเสีย

   ```bash
   sudo shutdown now
   ```

3. รอประมาณ 15 วินาที จนไฟสีเขียวของ Raspberry Pi หยุดกะพริบ แล้วค่อยปิดสวิตช์หุ่น

## ถ้าติดปัญหา

| อาการ | ลองทำ |
|---|---|
| `echo $ROS_DISTRO` ไม่ขึ้นอะไร | เปิดผิดตัว ให้ใช้ `wsl -d Ubuntu-22.04` |
| `hostname -I` ยังขึ้นต้นด้วย `172.` | ไฟล์ `.wslconfig` ยังไม่ถูก (ชื่อไฟล์ต้องไม่มี `.txt` ต่อท้าย) แล้วรัน `wsl --shutdown` อีกครั้ง |
| `ping` หุ่นไม่ได้ | โน้ตบุ๊กกับหุ่นอยู่คนละ Wi-Fi, IP ของหุ่นผิด หรือ Wi-Fi กันอุปกรณ์คุยกัน ลองใช้ hotspot มือถือ |
| `ssh` ถามรหัสผ่านแล้วไม่ผ่าน | ชื่อผู้ใช้หรือรหัสผ่านไม่ตรงกับที่ตั้งไว้บนหุ่น |
| bringup ขึ้นว่าเปิดพอร์ต `/dev/ttyACM0` ไม่ได้ | สาย USB ระหว่าง Raspberry Pi กับบอร์ด OpenCR หลวม หรือบอร์ดยังไม่ได้เปิด |
| bringup ฟ้องเรื่อง `LDS_MODEL` | ยังไม่ได้ตั้งค่า `LDS_MODEL` ในไฟล์ `~/.bashrc` ของหุ่น |
| `ping` ได้ แต่ `ros2 topic list` ไม่เห็น `/scan` | เช็คตามลำดับ: `ROS_DOMAIN_ID` ตรงกันไหม, ทำขั้น 1 ข้อ 3 (firewall) แล้วหรือยัง, เราเตอร์ส่ง multicast ไหม (ลอง hotspot มือถือ) |
| เห็น topic แต่ teleop แล้วหุ่นไม่ขยับ | เช็คว่าหน้าต่าง teleop ถูกเลือกอยู่ และแบตหุ่นไม่อ่อน |
| RViz ไม่ขึ้นตอนเปิด cartographer | ปิดแล้วเปิดเทอร์มินัล WSL ใหม่ หรือรัน `wsl --shutdown` แล้วลองอีกครั้ง |

ถ้าไล่ตามตารางแล้วยังไม่ได้ ให้คัดลอกข้อความ error ทั้งหมดมา แล้วบอกว่าติดที่ขั้นไหน
